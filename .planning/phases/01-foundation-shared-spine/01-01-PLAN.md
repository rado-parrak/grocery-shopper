## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Household member → resolution cascade | Vague/untrusted natural-language item requests cross into product resolution; hard constraints must filter first |
| Confirmation artifact → conversation | The only sanctioned crossing is the human's next chat turn; the artifact must never write to the cart or call a connector |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | resolution-cascade.md / household-ruleset.md | high | mitigate | §A hard constraints filter unconditionally and first; doc states a favourite can never override an allergy/never-buy (D-03) |
| T-01-02 | Elevation of Privilege | confirmation-protocol.md (artifact contract) | high | mitigate | Doc permanently forbids `mcp`/`downloads`/`storage` capabilities on the confirmation artifact; prototype issues zero network calls |
| T-01-03 | Spoofing (fake success) | mcp-degradation.md | high | mitigate | Read-back-after-write is the only success signal; degrade-to-manual on any failure; never report success from a write return value |
| T-01-04 | Information Disclosure | household-ruleset.md placeholders | medium | accept | Real allergies/dislikes are `⚠ FILL` placeholders here; the household fills them privately in plan 01-03; no personal data committed in this plan |
</threat_model>
